## What the evidence establishes

`agent-docs/test-audit/vet-evidence/bc63af5f-wave10/` records server PID 104411,
port 41011, and the first `CROSS-LOCK-008` empty reply before the later burst

AWS 21.0.0 keeps newly accepted first-header sockets and idle keep-alive sockets
in one acceptor set. `aws-net-acceptors.adb:283–286` can evict a non-ready socket
above the derived close threshold (256 with 64 workers; two auxiliary sockets
are added internally). Available historical traced cycles peak at 66 live
accepted sockets and do not demonstrate this eviction.

There is a separate worker-pressure path: `aws-server-protocol_handler.adb:205–223`
invokes `Force_Clean` when no worker is free. `aws-server.adb:631–678` can close
another expired abortable slot; forced client-header timeout is two seconds,
normal client-header timeout seven seconds. This path does not require the
acceptor count threshold. It is a source-level hypothesis, not the observed
cause of the reported failures.

The first historical traced burst received 41 HTTP 200 and 23 HTTP 400 headers
within 0.269 seconds, not empty replies. The batch lock admission's 200 one-ms
retries followed by `VALIDATION` could explain those 400s, but the old trace
truncated response bodies. Do not classify these responses as transport drops.
