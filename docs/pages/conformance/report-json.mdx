# Conformance report JSON

Run the suite against a server you started yourself with:

```sh
cd conformance
npx conformance run --against http://127.0.0.1:9600 --report json
```

The target is mandatory — there is no default server — and it must report
`testHooks: true` in `GET /api/health`, which only a server started with
`--test-hooks` does. Both rules exist so a test run can never write into a
campaign's data directory it did not create (see
[BUGFIX-1111](/conformance/bugfix-1111)). The managed launcher
(`npm run test:ada`) owns a throwaway data dir and satisfies both by itself.

The command writes one JSON document to stdout. A failed conformance run still
emits its report and exits non-zero, which lets CI retain the measurement while
using the exit status as its gate.

## Format

```json
{
  "schemaVersion": 1,
  "against": "http://localhost:9657",
  "results": [
    {
      "id": "SEMANTICS-BOUNDED-INTEGER-001",
      "name": "...",
      "suite": "suites/semantics/bounded-integer.test.ts",
      "status": "passed",
      "durationMs": 4.2
    }
  ],
  "summary": {
    "total": 1,
    "passed": 1,
    "failed": 0,
    "skipped": 0,
    "todo": 0
  }
}
```

`id` is the stable identifier used by CI and experiment scoring. `status` is
one of `passed`, `failed`, `skipped`, or `todo`. Failed results include an
`error` string; successful results omit it. Results are sorted by `id` so
reports are stable regardless of Vitest file execution order.
