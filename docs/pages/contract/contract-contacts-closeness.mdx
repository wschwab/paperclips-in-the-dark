# Contact closeness levels

**Ruling:** 2026-10-08, human. Contact closeness gains two levels, **confidante** and **enemy**, for a five-level scale:

`enemy < rival < contact < friend < confidante`

The default stays `contact`. Every contact is still a single family on the scoundrel sheet.

## Contract change

| Location | Change |
|---|---|
| `contract/schemas/common.json` `$defs.closeness` | enum becomes `enemy`, `rival`, `contact`, `friend`, `confidante` (was `friend`, `contact`, `rival`) |
| `contract/schemas/character.json` `contacts` | description names the five-level vocabulary and the create default |
| `contract/openapi.yaml` `contact.closeness` | description names the five-level vocabulary; request body still references `common.json#/$defs/closeness` |
| `contract/openapi.yaml` `createCharacter` | description states that the new scoundrel's contacts are preloaded |

No operation is added or removed. `contact.add` still defaults to `contact`. `contact.closeness` with a value outside the five levels is still a VALIDATION error.

## Create default: playbook contacts are preloaded

Human-authorized 2026-10-08. A new scoundrel is created with its playbook's Rolodex friends (`data/games/*.json`, `Playbooks[].Rolodex.Friends`) at closeness `contact`. The server does this in `New_Character` (`backend-ada/server/src/pitd_ops.adb`), so API callers get the same result as the sheet. Blades in the Dark: 7 playbooks, 35 friends in total.

## Conformance

`conformance/suites/semantics/character-contacts-levels.test.ts` is a new, additive suite. It sets `confidante` and `enemy` and reads them back (`CONTACTS-LEVELS-001`), and rejects a value outside the scale (`CONTACTS-LEVELS-002`). The frozen three-level suite's loop (`friend`, `rival`, `contact`) is unchanged.

`conformance/src/schemas.ts` mirrors the contract's closeness enum for the conformance client's request side. It was updated to the five values. This is a schema mirror, not a frozen test, and it is a recorded exception to the no-conformance-edit rule.

## Frontend

Closeness decoders (`frontend/src/schema/common.ts`) take the five values. `CONTACT_CLOSENESS_ORDER` gives the cycle order: each click moves one level up, and `confidante` wraps to `enemy`. Each level has its own bold, bordered badge with white text; contrast was measured in Chromium in light, dark, and high-contrast themes (`browser-evidence/playtest-ui-02/c-summary.json`, minimum ratio 4.54:1). The badge is a button with class `contact-closeness` and a "Cycle closeness" title. Remove and add-custom are unchanged.
