# Setting content register

This page records where official setting material currently lives, and the steps to fold the private research draft back in if the community and the rights holder agree. It contains **no official names**. The licence boundary is in [Crew world data: verified scope and options](./crew-world-sources.mdx).

## The private draft

- Location: `~/code/private-crew-world/doskvol-draft.json` (outside the repository, not committed).
- Counts: **11 districts** and **49 faction rows**. The faction rows split into five groups: 16, 14, 10, 8 and 1.
- Provenance: transcribed from the official Factions of Doskvol campaign-tracking sheet. The licence page excludes the setting, so the draft is research material, not approved data.
- A visual check found a layout judgement the draft makes that may not match the sheet (the grouping of one Citizenry row). Re-verify before use.

## Fold-back steps (only with written permission)

Do these only after the rights holder grants permission in writing and the grant is recorded in the crew world card.

1. **Data file.** Add a `data/world/` file that holds the approved names, tiers and holds, with source and attribution fields. Validate it against a schema first. Do not copy the research draft as is; re-check every row against the grant.
2. **Stock faction picker.** Add a picker to the faction editor in `frontend/src/pages/crew-sections/contacts.ts` that reads the new file. The manual entry stays as the fallback. Starting ally and rival pickers keep drawing from the crew's own factions, so a stock choice becomes an ordinary crew faction only when the user adds it.
3. **Districts disclosure.** Add a collapsed districts section that shows each approved district with its description and location text, only if the grant covers those descriptions. Otherwise show names only.
4. **Attribution.** Update the README copyright section and the sources page with the grant's wording, the licence and the publisher contact. Keep the CC-BY 3.0 Unported statement for the SRD content.
5. **Tests and gates.** Add a red test for the picker and for the disclosure before the UI change. Run the full suite, the browser journeys, and a Sol review of the range.
6. **Publication.** Confirm the research draft is absent from every commit in the range you push. Do not push a history that contains the draft.
