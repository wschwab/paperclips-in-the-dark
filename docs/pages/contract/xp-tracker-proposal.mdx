## Approved Score layout

The separate **XP Tracker** appears **only in Score**, with **Desperate action
XP**, **Playbook expressions**, **Scoundrel expressions**, and **Struggle
expressions**. It is not a new scoundrel-sheet section or a fourth game mode.
At widths **1100px and above**, use a distinct panel under/next to Game mode.
Below **1100px**, the fixed footer has a small **XP Tracker** button opening a
bottom sheet. Reuse the existing game-mode `mockup.css` imports, fonts, theme
controls and 06d Resolution styling, with Nyelle Vale / Wren, the Lurk.

The sheet still contains **Personal**, the **playbook XP track**, all
**attribute XP tracks**, and every other existing section. Moving session
controls into the tracker does not remove advancement controls or create a
mode gate. This is per-scoundrel assistance, never campaign-wide state.

### Compact interaction and accessibility

- Use a real button with `aria-expanded` and `aria-controls`, not a draggable
  label masquerading as a control. Tap/click and Enter/Space toggle the sheet.
- Provide a named sheet, visible focus, an explicit Close button and Escape
  dismissal. Return focus to the opener. An expanded modal sheet contains
  focus and makes the background inert.
- Dragging the handle adds pointer/touch convenience; every open/close action
  remains possible without dragging. Content scrolling must not inadvertently
  become a dismiss gesture.
- Reserve space for the fixed footer and safe-area inset; keep controls
  reachable at 390px. Respect reduced motion without disabling interaction.

## Resolution: explicit conversion, then clear

Keep the existing six steps:

**Scoundrel XP → Payoff → Heat → Entanglements → Crew XP → Crew Rep**.

Retain Back/Next, direct step selection, confirm-with-GM guidance, separate
crew-targeted editors and optional Crew XP/Crew Rep skips. Resolution remains
within Score; choosing another mode, closing/resuming the flow or revisiting
a step must not replay an award.

**Desperate action XP is granted during play.** Mark 1 in the rolled action's
attribute immediately, including desperate group actions. That XP is already
on the permanent attribute track and is not included again in conversion.

**Expression counters are session reminders, not XP grants.** For each
trigger record 1 if it happened, 2 if it happened a lot, zero if it did not.
Scoundrel XP reviews these reminders and explicitly assigns the expression
XP to any playbook and/or attribute tracks. For example, **2 + 1 + 1 = 4** may
all go to one chosen track; players may also split it. This is the SRD's
end-of-session review offered at score resolution, not an automatic award
for each score or a mandatory session reset whenever a score ends.

**Completing Scoundrel XP clears the three session expression counters after
conversion.** Show a clear notice explaining this timing. Permanent playbook
and attribute XP are retained; their clears are advancement operations, not
session cleanup. Opening the step or navigating Back/Next alone is not a
conversion. Remove the old sheet **End downtime clears expressions** control
and responsibility in the later implementation. Nothing in this mockup
changes today's End Downtime API.

## Current contract and implemented behavior

These are source-inspection findings, not newly exercised verification.

| Operation | Current behavior | Exact source references |
|---|---|---|
| `session.set` | Partial absolute counter update clamped to game-settings maximum; no XP award, no snapshot. Zero clears a counter. | `contract/openapi.yaml:1657–1674`; `backend-ada/server/src/pitd_ops.adb:1482–1513`; zero/clamp oracle `conformance/suites/semantics/session-set.test.ts:7–28` |
| `playbook-xp.add`, `attribute-xp.add` | Explicit signed delta to permanent XP, clamped by the track maximum. This is when XP is granted, not when a session counter is marked. | `contract/openapi.yaml:1230–1240,1257–1273`; `pitd_ops.adb:972–981,1029–1039` |
| `playbook-xp.clear`, `attribute-xp.clear` | Clears permanent advancement tracks, not session counters. Attribute level-up spends its track; ability-taking does not automatically clear playbook XP. | `contract/openapi.yaml:1246–1250,1279–1293,1303,1347`; `pitd_ops.adb:982,1029–1030` |
| `end-score` | Explicitly **no automatic XP**. Opens Resolution at Scoundrel XP; retains committed gear by default, preserves partial stress, resets downtime budget/out-of-action flags. | `contract/openapi.yaml:1700–1723`; `pitd_ops.adb:1737–1786` |
| `mode.flow.set` | Freely selected assistance cursor; Back/Next/direct selection never grants XP, performs cleanup or resets downtime. | `contract/openapi.yaml:1771–1783`; `pitd_ops.adb:751–755` |

The existing source oracles constrain the cutover:

- `conformance/suites/lifecycle/lifecycle-state-machine.test.ts:237–275`
  freezes pending-trauma rejection, partial-stress preservation, single
  snapshot and undo behavior for End Score.
- `conformance/suites/semantics/game-mode.test.ts:376–411` asserts End Score
  enters Resolution while preserving playbook/talent state, plus replay/undo.
- `conformance/suites/semantics/composites.test.ts:135–165` explicitly sends
  `clearSessionExpressions:true` to End Downtime and asserts all three zeros,
  stress relief and exactly one snapshot.
- `frontend/src/pages/character-sections/talents.ts:187–198` currently exposes
  the old End Downtime clear button and copy.

### Does clearing at Resolution need a contract change?

**The explicit clearing primitive already exists:** XP-add operations followed
by `session.set` with all three zeros can represent conversion/clear without
a new endpoint. But those separate operations do not define an atomic,
replay-safe completion or a persisted allocation record. **Do not add hidden
awards or clearing to `mode.flow.set`**: its contract explicitly forbids them.

**The approved full clean cutover requires later contract work.** Removing
End Downtime's public `clearSessionExpressions` responsibility changes an
existing declared behavior and frozen composite oracle. The implementation
card must update contract, backend, all callers and affected tests together,
and define Scoundrel XP completion semantics. This proposal does not
implement that change or claim it already exists.

## Decisions still open

1. Should conversion plus clearing be one atomic server completion operation,
   or explicitly coordinated existing mutations? Cursor movement stays
   assistance-only regardless.
2. How should a full track or allocation exceeding available capacity interact
   with advancement and remaining XP? Current XP-add clamps; silently clearing
   expression XP that was not credited has not been approved.

Placement, breakpoint, labels, retained sheet sections, six steps and clear
at Scoundrel XP completion are already decided and are not reopened here.
