# Enforced-limit inventory

**Card:** SC-R4 (Wave 0 research). **Date:** 2026-08-14.
**Governing decisions:** [Ordered work specification](/contract/spec-change-work-spec), "Limits and capabilities" and "Numeric operation results".
**Method:** grep-verified literals only; every file:line below was produced by actual search of the cited file. Sources surveyed: `contract/schemas/*.json`, `contract/openapi.yaml`, `backend-ada/core/src/`, `backend-ada/server/src/`, `frontend/src/`, `data/games/*.json`, and the authoritative reference `blades-in-the-sheets/Models/` (C#).

## Summary

Every client-visible bound enforced today falls into one of five classes:

| Class | Meaning | Where published today | Count (rows below) |
|---|---|---|---|
| **game-domain** | Game rules maxima/lists; differ per supported game | Mostly **hardcoded in the Ada server**; a few already in settings | 29 |
| **derived** | Server-computed from settings + cross-entity state; never persisted | Computed ad hoc in Ada server and frontend | 9 |
| **request** | Inbound request body/header bounds | Already in OpenAPI/schemas (partially enforced by server) | 6 |
| **service** | Payload/batch/history/idempotency operation limits | Hardcoded Ada constants; some mirrored in OpenAPI | 4 |
| **internal** | Implementation capacities that cannot fail a client | Hardcoded Ada constants | 8 |

**Bottom line:** the Ada server's *defaults* at entity creation are hardcoded game-domain literals (`pitd_callback.adb:1076,1079,1089,1115`); subsequent enforcement of most trackers reads the entity's own `max` field, so the literal only pins the initial value. Two OpenAPI promises are **not enforced by the server at all**: `upgrade.mark` → `UPGRADE_MAXED` (TotalBoxes) and per-commitment load max bulk. The frontend consciously parameterizes maxima (`stress-track.ts:24` "never hardcode a game maximum") but hardcodes the turf row (6) and the develop coin cost formula `(tier+1)×8`.

## 3. Derived-limit list — capability projections, never persisted

Per the governing "Limits and capabilities" decision and Q19/Q20/Q41, these become server-computed projections. None may be stored in byte-identical entity DTOs:

1. **Character capabilities**: effective action caps (`effectiveActionCap` per action = `min(maxRating, crew-derived cap)`); harm capacities (per-level slots and remaining); load limits (per-commitment max bulk incl. ability raises); armor availability; available ability takes.
2. **Crew capabilities**: full available upgrade catalog (`upgradeId`, `totalBoxes`, `marked`, `remaining`, coin affordability); full available ability catalog (`maxTakes`, `taken`); `effectiveTurf`; `developThreshold`.
3. **Service capabilities**: `maxPayloadBytes`, `maxHistorySnapshots` (and batch bound if published).
4. **Roster/detail derived state**: `canUndo`, `historyCount` (Wave 1 lifecycle decision).

Today these are computed ad hoc: frontend joins game data + DTO state (`crew-detail.ts:378-400,690,703-726,1047-1081`), server recomputes (`Rating_Cap`, `Turf_Effect_Delta`, `Armor_Available`), and one derived value — armor `has*` — is persisted in the DTO today (`character.json` `monitor.armor.hasStandard/heavy/special`), which Q41 says must move to projections or gain an explicit exemption.

## 5. Internal-capacity list — never an API promise

- Idempotency LRU capacity 32 (`pitd_callback.adb:116`) — eviction silently narrows the replay window; the API must not promise durable replay. Exposed keys *are* scoped to method+route+entityId+key with SHA-256 body hash (`pitd_callback.adb:2272-2294`).
- Entity lock table 64 (`pitd_callback.adb:48`) — bounded concurrency; wait, never fail.
- SPARK `Capacity = Positive'Last / 4` (`paperclips_core.ads:8`) — proof-friendly ceiling for all trackers/clocks/gear; cannot be reached through the API.
- Snapshot id generation (`pitd_callback.adb:335-340`) — the *shape* is published (`campaign.json:86` pattern), generation internals are not.
- History scan buffers 1..1024 (`pitd_callback.adb:460,559`) — unreachable past 50 given pruning.
- `Integer'Last` guards on coin/stash/tier deltas (`pitd_callback.adb:1648-1650`) — arithmetic ceiling.
- Revision arithmetic (+1 per write; `pitd_callback.adb:1128,2365,2395`) — unbounded above `minimum: 1`; overflow is an internal concern.
- Clock overflow/rollover mechanics (`paperclips_core-clocks.ads`) — published *results* via `applied`/`overflowAdded` (SC-C2), never a capacity promise.
