# Lifecycle transition matrix

**Card:** SC-R5 · **Wave:** 0 · **Status:** frozen for SC-S1, SC-C2, SC-O6, SC-A8, SC-F4
**Normative source:** `docs/pages/contract/spec-change-work-spec.mdx` § "Character lifecycle" (locked rules) and Q33/Q42 of its decision ledger. The C# reference (`blades-in-the-sheets/Models/`) remains authoritative for existing domain semantics; where it conflicts with a locked rule, the locked rule wins and the conflict is recorded in § 11.

## 1. Scope

This document freezes, for every lifecycle transition:

- **preconditions** (including the four lifecycle flags);
- **atomic state changes** (every field touched);
- **errors** (`TRAUMA_REQUIRED`, `RETIRED`, `CONFIRM_REQUIRED`, `STALE_REVISION`, `OUT_OF_ACTION`, …);
- **allowed next operations**;
- **undo behavior** (complete prior-state restore? snapshot-worthy?);
- **snapshot-worthy flag**.

It also freezes the retired-operation allow-list and deny-list, the single shared cleanup function used by both retirement paths, the deadish transition design, end-score rules, the `canUndo`/`historyCount` derivation, the SC-O6 conformance case list, and the current-behavior conflicts SC-A8 must fix.

**Transitions covered (8):** stress reaching maximum · trauma resolution · end-score (normal and with pending trauma) · explicit retirement (confirmed) · final-trauma retirement · fatal harm applied (deadish) · fatal harm removed (recovery) · deletion.

## 2. State model

### 2.1 Flags

| Flag | Storage | Semantics |
|---|---|---|
| `isRetired` | stored canonical boolean | Set only by the shared retirement cleanup (explicit retire or final-trauma resolution). **Never recomputed from the trauma count.** |
| `traumaPending` | stored canonical boolean (new) | True from the moment stress reaches maximum until the pending trauma is resolved. |
| `isOutOfAction` | stored canonical boolean (new) | True from trauma resolution until `end-score` (or retirement/deadish cleanup). Character is out of action for the remainder of the score. |
| `stressClearPending` | stored canonical boolean (new) | Set and cleared together with `isOutOfAction`; records that `end-score` owes a stress clear. |
| `isDeadish` | stored canonical boolean, **write-time derived** | Recomputed from `monitor.harm.fatal` (non-empty) at the end of every transition that touches harm or lifecycle state. No operation accepts it as input; it is never a free-standing toggle (locked rule). Mirrors C# `IsDeadish => Monitor.Harm.IsFatal`. |
| `canUndo`, `historyCount` | never stored | Derived at response time (§ 9). |

### 2.2 Invariants (no transition may violate)

- `¬(traumaPending ∧ isOutOfAction)` — pending and out-of-action never co-occur (pending is cleared by the same transition that sets out-of-action).
- `stressClearPending ⟺ isOutOfAction` — the two flags are set and cleared together, by every transition that touches either.
- `isDeadish ⟺ monitor.harm.fatal non-empty` — checked at the end of every transition.
- `isRetired` once true stays true until an undo restores the prior snapshot (undo is the only recovery path; `trauma.remove` never clears it).
- A transition sets `traumaPending` only when stress moves from below max to exactly max; it never auto-adds trauma.
- Stress is kept full from trauma resolution until `end-score` (Q42); the only sanctioned clears in that window are `end-score`, the retirement/deadish cleanups, `end-downtime` vice relief (GM judgment), and undo.

### 2.3 Gates (who is blocked when)

| Condition | Blocked operations | Error |
|---|---|---|
| `isRetired` | All gameplay mutations (deny-list, § 6.2) | `RETIRED` |
| `isRetired` | Allow-list ops (dossier/name/notes/notebook/trauma.remove/undo/delete/import/reads, § 6.1) | — allowed |
| `traumaPending` | Gameplay mutations, `stress.add`, `stress.clear`, `end-score` | `TRAUMA_REQUIRED` (detail: resolve pending trauma first) |
| `traumaPending` | `trauma.add` | — allowed (this is the resolution) |
| `isOutOfAction` | `stress.add`, `stress.clear` | `OUT_OF_ACTION` (new code; detail: character is out of action until end-score) |
| `isOutOfAction` | Everything else | — allowed (consequences, harm, and bookkeeping continue; the flag is a declared state, and the locked rule phrases the client obligation as explanation) |
| `isRetired` or `traumaPending` | `retire` / `trauma.add` (respectively) | `RETIRED` / — retirement is allowed while pending; `trauma.add` while retired → `RETIRED` |

`OUT_OF_ACTION` is a new error code: SC-C4 must add it to the typed error union (the SC-C4 list is "at least" those codes). The gate exists to keep Q42's "stress remains full until end-score" airtight and to make re-pending while out-of-action unreachable (§ 2.2).

## 4. End-score rules (frozen)

1. **`TRAUMA_REQUIRED` rejection:** while `traumaPending` is true, `end-score` fails with `TRAUMA_REQUIRED`; the pending trauma must be resolved first. End-score can never erase an unresolved trauma (card acceptance).
2. **Inherent cleanup:** a successful `end-score` always clears `monitor.stress.current → 0` and resets both out-of-action flags (`isOutOfAction`, `stressClearPending`), regardless of the optional flags in the body.
3. **One-snapshot atomicity:** the whole composite — stress clear, both flag resets, and every selected optional cleanup (`clearArmorUsed`, `resetLoadoutCommitment`) — lands in **one snapshot and exactly one history entry**. A mid-composite failure (e.g. `COMMITMENT_LOCKED` from `resetLoadoutCommitment`) fails the whole operation: nothing is applied, no snapshot is written.
4. **Body optional:** the current "at least one flag" requirement (openapi.yaml:1305–1308, pitd_callback.adb:1306) is dropped; an omitted/empty body is a valid end-score (stress + flag cleanup only). SC-C2 updates the request schema (drop `minProperties: 1`, body no longer `required`).
5. **Gates:** `isRetired` → `RETIRED`; `traumaPending` → `TRAUMA_REQUIRED`; `isOutOfAction`/deadish do not block (out-of-action is exactly what end-score releases).
6. Undo of `end-score` restores the complete prior state from the single snapshot (locked rule: undo restores the complete prior state).

## 5. Deadish design (frozen)

- **Cause:** only fatal harm. `isDeadish` is never a free-standing toggle — no operation accepts it as input; it is recomputed from `monitor.harm.fatal` at the end of every transition (write-time derivation, as the Ada server already does for harm ops, pitd_callback.adb:1502/1505/1875).
- **Distinct from retirement:** deadish preserves **all** harm (including fatal), the healing clock, and armor usage; retirement clears all of them. Deadish sets no gate of its own (no locked rule blocks deadish characters from operations; consequences and recovery must remain possible).
- **Deadish cleanup (on becoming deadish, § 7.2):** clears stress and all pending/out-of-action state; preserves harm, healing clock, armor, and every other field.
- **Fatal-harm removal (recovery):** `harm.remove` (exact intensity `fatal`) or `harm.heal` (requires full healing clock) removes the fatal harm; `isDeadish` recomputes false when the fatal array is empty. Deadish is a state, not a lock: recovery does not require any special operation.
- **Retirement overrides deadish:** retirement cleanup clears harm, so a deadish character who retires ends the session non-deadish (recomputed). This is the locked "retirement clears harm" rule; it is not a contradiction.
- **Coexistence:** a deadish character can still accrue stress (→ pending → resolution → out-of-action); the deadish cleanup only fires on the fatal transition itself.

## 6. Retired-operation allow-list and deny-list (frozen)

The `RETIRED` gate (currently pitd_callback.adb:1439–1441) must be replaced by these two explicit lists. Reads are always allowed.

### 6.1 Allow-list (proceed normally on a retired character)

| Operation | Rationale |
|---|---|
| `dossier.update` (name, alias, look, heritage, background, vice, crewId) | Locked rule — dossier and named-field edits remain allowed ("permit the non-mechanical dossier edits needed to finish their record"; completeness is unaffected by retirement) |
| `note.add`, `note.remove` | Locked rule — note edits remain allowed |
| `notebook.set` | Locked rule — notebook edits remain allowed |
| `trauma.remove` | Locked rule — removing trauma must not silently reverse retirement; this is the trauma-history correction path. **Never recomputes or clears `isRetired`** |
| `undoCharacter` | Locked rule — lifecycle recovery remains available; restores the complete prior state (this is the sanctioned way to reverse a retirement) |
| `deleteCharacter` (confirm + If-Match) | Locked rule — retired characters remain deletable |
| `importCharacter` | Data management, not gameplay (full-DTO replacement); the imported document is canonical and may deliberately change lifecycle flags; on import `isDeadish` is recomputed from the imported harm arrays (normalization rule, prevents contradictory imports); import clears history and takes one baseline snapshot (existing contract) |
| All reads: `getCharacter`, `listCharacterHistory`, `getCharacterSnapshot`, roster/list | Locked rule — retired characters remain readable |

### 6.2 Deny-list (→ `RETIRED` on a retired character)

All gameplay mutations: `stress.add`, `stress.clear`, `trauma.add`, `harm.add`, `harm.remove`, `harm.heal`, `harm.healing-clock`, `armor.set`, `playbook-xp.add`, `playbook-xp.clear`, `attribute-xp.add`, `attribute-xp.clear`, `attribute.levelup`, `action.set-rating`, `ability.take`, `ability.remove`, `gear.add`, `gear.remove`, `gear.commit`, `gear.uncommit`, `gear.set-commitment`, `gear.clear-commitments`, `gear.lock`, `gear.unlock`, `fund.gain`, `fund.spend`, `fund.liquidate`, `rolodex.add`, `rolodex.remove`, `rolodex.set-closeness`, `session.set`, `end-score`, `end-downtime`.

**Interpretation note (frozen):** the locked phrase "lifecycle cleanup and undo remain available" is realized as (a) undo and delete remain on the allow-list, (b) the shared retirement cleanup (§ 7.1) remains the single transition used by both retirement paths, and (c) `end-score`/`end-downtime` are denied because a retired character is out of the score/downtime loop. If a retirement was a mistake, undo — not a follow-up mutation — is the recovery path.

## 7. Cleanup functions

### 7.1 Shared retirement cleanup — ONE function used by BOTH retirement paths

Frozen decision (card contract): explicit retirement (`retire`) and final-trauma retirement (`trauma.add` at max) call the **same** cleanup. Observable consequence for SC-O6: both paths produce identical post-cleanup state modulo the preserved trauma history.

Exact field effects (applied atomically, one snapshot, revision +1):

| Field | Effect |
|---|---|
| `isRetired` | → `true` |
| `monitor.stress.current` | → `0` |
| `traumaPending` | → `false` |
| `isOutOfAction` | → `false` |
| `stressClearPending` | → `false` |
| `monitor.harm.lesser`, `.moderate`, `.severe`, `.fatal` | → `[]` (all harm cleared) |
| `monitor.harm.healingClock.segments` | → `0` |
| `monitor.harm.healingClock.rollover` | → `0` (reset discards overflow) |
| `monitor.armor.standardUsed`, `.heavyUsed`, `.specialUsed` | → `false` |
| `isDeadish` | → `false` (recomputed: fatal empty) |
| `dossier` (name, crewId, alias, look, notes, background, heritage, vice) | preserved verbatim |
| `playbook` (name, experience, abilities) | preserved verbatim |
| `monitor.trauma` (traumas, max) | preserved verbatim (trauma history is kept) |
| `talent` (attributes, XP tracks) | preserved verbatim |

Runs only inside the fatal-harm transition (fatal 0 → 1). Exact field effects (one snapshot, revision +1):

| `traumaPending` | → `false` |
| `isOutOfAction` | → `false` |
| `stressClearPending` | → `false` |
| `monitor.harm` (all intensities, incl. the fatal harm just added) | **preserved** |

| `isDeadish` | → `true` (recomputed) |

## 8. Stress/trauma sequence (locked, restated for SC-S1)

1. `stress.add` landing at max → `traumaPending: true` + typed attention (sideEffect token `"stress full — trauma pending"`; SC-C2 freezes the exact string); never auto-trauma.
2. `trauma.add` (resolution) → records the trauma, keeps stress **full**, clears `traumaPending`, sets `isOutOfAction` + `stressClearPending`. If it was the final trauma → shared retirement cleanup in the same transition.
3. `end-score` while `traumaPending` → `TRAUMA_REQUIRED`.
4. Successful `end-score` → stress → 0, both out-of-action flags reset, selected score cleanup, one snapshot.
5. Clients explain that the character is out of action for the remainder of the score (SC-F4 obligation).

## 9. `canUndo` / `historyCount` derivation (frozen)

- **Never stored** (locked rule: "No stale derived flag is persisted"; Q34). Computed at response time for roster summaries and character detail responses.
- `historyCount` = number of retained snapshot entries in the entity's history (0..50, retention cap per PERSISTENCE-SNAPSHOT-002); `canUndo = historyCount > 0`.
- Snapshot-worthy transitions (all rows marked **Yes** in § 3, plus `importCharacter`) increment; `x-snapshot: false` micro-ops (`stress.clear`, `armor.set`, `harm.healing-clock`, `session.set`, `notebook.set`, undo, delete) do not. Undo consumes one snapshot → `historyCount` decrements. Delete removes the entity, projections gone.
- Projection cost: derived from the existing history index; no history files are touched on read.

## 11. Current-behavior conflicts SC-A8 must fix (file:line)
