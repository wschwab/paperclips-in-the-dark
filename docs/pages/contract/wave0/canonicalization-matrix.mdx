# Canonicalization and repair matrix

**Card:** SC-R0 (Wave 0, research). **Output of:** the ordered work specification,
"Canonical shape and normalization" and "Stored-entity classification and HTTP errors"
sections, plus decisions Q1–Q9/Q13–Q15/Q26. **Sources:** `contract/schemas/` (five entity
schemas + `operation-result.json`), `PAPERCLIPS.md` §6/§7.1, `blades-in-the-sheets/Models/`
(legacy C# reference), `data/games/game-settings-schema.json` and game files.

The normalizer has exactly four outcomes (work spec, canonical shape §10):

| Outcome | Meaning |
|---|---|
| `canonical` | readable without changes; GET returns the stored bytes byte-identically |
| `repairable` | a schema-valid canonical result can be produced and previewed (fills, conversions, clamps, listed removals) |
| `needs-input` | the preview identifies exact pointers that require caller-supplied values |
| `unreadable` | bytes cannot be parsed as a recoverable entity object; no normalization is possible |

HTTP outcomes are fixed by the work spec (stored-entity classification) and reused here
verbatim:

| Outcome | Meaning |
|---|---|
| `400 VALIDATION` | invalid inbound request syntax or shape (create/import/repair request body) |
| `400 INVALID_ENTRY` | submitted import/repair content that cannot be normalized with the supplied values; pointer-level details |
| `422 INVALID_ENTITY` | a parseable stored entity requiring explicit repair, or unparseable stored bytes, on **direct access**; collections remain `200` |
| `409 NORMALIZATION_REQUIRED` | a normalization preview requiring confirmation before a lossy or material rewrite; carries warnings and a preview token |
| `409 STALE_REVISION` | changed revision, or degraded content token no longer matching the current raw bytes |
| `404 NOT_FOUND` | missing path |
| `200` | collections and roster remain `200` even when members are degraded; canonical direct GET returns `200` byte-identical |

## 1. Defect-class matrix

Ten defect classes. Columns: canonical default availability; preview warning;
required caller input; HTTP outcome; write/no-write behavior; test fixture.
"Stored" = persisted entity; "inbound" = create/import/repair request content.
Direct-access rows assume a stored entity; collection endpoints always stay `200`
(total-collection rule).

| # | Defect class | Canonical default availability | Preview warning (example) | Required caller input | HTTP outcome | Write/no-write behavior | Test fixture |
|---|---|---|---|---|---|---|---|
| D1 | Missing key | Yes for most properties (canonical empty per §3); **no** for `needs-input` properties (see §3) | `Missing required property <ptr>: filled with canonical default <default>` / `…requires a caller-supplied value` | None when a canonical default exists; the exact value otherwise (e.g. clock `size`, `createdAt`, enum without neutral) | Stored: direct GET `422 INVALID_ENTITY` (repairability or needs-input details); repair preview `409 NORMALIZATION_REQUIRED`; apply `200`. Inbound import: preview `409`; apply `200`; apply without values for needs-input pointers `400 INVALID_ENTRY`. Create: `400 VALIDATION` | Reads never write. Repair/import apply atomically writes the previewed document, requires `If-Match` + preview token + confirmation, and takes exactly one baseline history snapshot (import). No write until confirmed | `F1` |
| D2 | `null` value | Same as missing key (`null` is never stored; missing and `null` are the same defect) | `Property <ptr> is null (null is never stored): normalized to <default>` | Same as D1 | Identical to D1 | Identical to D1 | `F2` |
| D3 | Wrong primitive type | No — coercion, where safe, is a previewed conversion; otherwise no result without input | `Property <ptr> had type <T>, expected <U>: converted to <value>` / `…cannot be converted` | None for lossless coercions (integer string ↔ number, boolean strings `"true"`/`"false"` ↔ boolean, number → string); the value itself for anything else (object → scalar, non-integer string → integer, `null` inside arrays, …) | Stored: coercible → direct GET `422 INVALID_ENTITY`, preview `409 NORMALIZATION_REQUIRED`, apply `200`; uncoercible → `422 INVALID_ENTITY` with needs-input pointers. Inbound: preview `409` / apply `200`; uncoercible `400 INVALID_ENTRY`. Create: `400 VALIDATION` | No write until confirmed apply; preview shows every coercion with pointer and replacement | `F3` |
| D4 | Wrong enum value | No — but known **legacy variants** convert deterministically (L2); unknown variants need input | `Property <ptr> value '<v>' is not in <enum>: mapped from legacy variant to <value>` / `…not a known variant; requires a caller-supplied value` | None for known legacy variants (e.g. `"Strong"` → `"strong"`); the correct enum value otherwise | Stored: legacy variant → `422` + preview `409` + apply `200`; unknown variant → `422 INVALID_ENTITY` (needs-input). Inbound: preview `409` / `400 INVALID_ENTRY`. Create: `400 VALIDATION` | No write until confirmed apply; legacy mappings are explicit rules (L2), never guesses | `F4` |
| D5 | Invalid numeric bound | No — repair is a deterministic **clamp** to the declared `minimum`/`maximum`, previewed as a material rewrite | `Property <ptr> value <v> is outside [<min>, <max>]: clamped to <bound>` | None when a bound is declared in the schema (clamp is deterministic); caller input for settings-derived maxima that cannot be resolved (missing/unresolvable `gameStem`) | Stored: `422 INVALID_ENTITY`; preview `409 NORMALIZATION_REQUIRED` (lossy — confirmation required); apply `200`. Inbound: preview `409` / apply `200`. Create: `400 VALIDATION` | No write until confirmed apply; the clamp is visible in the preview with previous and replacement values | `F5` |
| D6 | Unknown / undeclared key | No — unknown keys are never defaulted; they are **removed only through an explicitly displayed, confirmed action** (no silent unknown-key loss, Q9) | `Unknown property <ptr> will be removed (data loss); removal must be confirmed` | None for removal (caller confirms); caller input if the key should instead be mapped to a canonical property | Stored: direct GET `422 INVALID_ENTITY`; preview `409 NORMALIZATION_REQUIRED` listing every removal; apply `200`. Inbound: `400 INVALID_ENTRY` **unless** the preview explicitly classifies and displays the removal, then preview `409` / apply `200`. Create: `400 VALIDATION` | No write until confirmed apply; the preview enumerates each unknown key (JSON pointer, reason `undeclared`, previous value) — removal is never silent | `F6` |
| D7 | Known legacy shape | Yes — every legacy shape has an explicit conversion rule (L1–L8); the converted value is always schema-valid | `Legacy shape at <ptr>: converted per rule L<n>: <before> → <after>` | None for documented legacy shapes (notes string, dictionary-by-name, PascalCase enums, C3-era absent contacts/factions, legacy clocks); caller input when the legacy document is ambiguous (e.g. modern-shape clock missing `clockKind`) | Stored: `422 INVALID_ENTITY`; preview `409 NORMALIZATION_REQUIRED`; apply `200`. Inbound: preview `409` / apply `200`. Create: n/a (canonical by construction) | No write until confirmed apply; conversions are explicit rules, listed with reason and replacement | `F7` |
| D8 | Wrong identity (`kind`/`id` mismatch) | No default — the **route identity is authoritative** (Q15): the body is normalized to the directory location | `Body <kind>/<id> does not match route <kind>/<id>: normalized to route identity (directory is authoritative)` | None when the body validates after the identity fix (kind and id are both supplied by the route); otherwise the remaining `needs-input` pointers; a body of a wholly different entity type needs the caller's decision (repair or delete + re-import) | Stored: direct GET `422 INVALID_ENTITY` (degraded row keeps route-derived id/kind in collections); preview `409 NORMALIZATION_REQUIRED`; apply `200`. Inbound import into a mismatched collection (crew body into `characters/`): `400 INVALID_ENTRY`. Create: `400 VALIDATION` | No write until confirmed apply; the preview shows the identity change; unreadable identity bodies can only be deleted (token-guarded) | `F8` |
| D9 | Non-object root | No — a parsed value that is not an object (`[]`, `"x"`, `42`, `null`) is not a recoverable entity object | `Document root is not an entity object; unreadable — cannot be normalized` | None possible; the caller may delete and re-import | Stored: direct GET `422 INVALID_ENTITY`; collections `200` (degraded row: route id/kind, `isReadable:false`, `isRepairable:false`, `deleteToken` = `sha256:<hex>` of raw bytes). Inbound: `400 VALIDATION` | No normalization write, ever; deletion only, guarded by the raw-byte token (`If-Match: sha256:…`); changed bytes → `409 STALE_REVISION` | `F9` |
| D10 | Unparseable bytes | No — bytes that do not parse as JSON (invalid UTF-8, truncation, trailing garbage) are unreadable | `Bytes cannot be parsed as JSON; unreadable — cannot be normalized` | None possible; the caller may delete and re-import | Identical to D9 | Identical to D9 | `F10` |

Classification of the ten classes into the four normalizer outcomes:

| Outcome | Classes |
|---|---|
| `canonical` | none of the ten — a document with no defect |
| `repairable` | D1/D2 (with default), D3 (coercible), D4 (legacy variant), D5, D6 (with displayed removal), D7, D8 (when body validates after identity fix) |
| `needs-input` | D1/D2 (no default), D3 (uncoercible), D4 (unknown variant), D8 (remaining pointers), plus any repair whose preview ends with pointers awaiting caller values |
| `unreadable` | D9, D10 |

## 2. Legacy conversion rules

The C# `blades-in-the-sheets/Models/` tree is authoritative for legacy domain
semantics. The confirmed legacy wire shapes are camelCase documents (matching the
current DTO style) with the following known differences; each conversion is an
explicit, previewed rule — never a silent rewrite:

| Rule | Legacy shape (source) | Canonical result | Notes |
|---|---|---|---|
| L1 | `notes: "string"` (single string) — `Dossier.Notes`, `Crew.Notes` | `notes: ["string"]`; `""` → `[]` | C4 playtest change (2026-08-09); frontend decoders already accept the legacy string |
| L2 | PascalCase C# enum serialization — `Strong`/`Weak` (CrewHold), `Friend`/`CloseFriend`/`Rival` (FriendCloseness), `None`/`Light`/`Normal`/`Heavy`/`Encumbered` (LoadCommitmentOption), `Gang`/`Expert` (CohortType), `Healthy`/`Weakened`/`Impaired`/`Broken`/`Dead` (CohortHarmLevel), `Fearsome`/`Independent`/`Loyal`/`Tenacious` (CohortEdge), `Principled`/`Savage`/`Unreliable`/`Wild` (CohortFlaw) | canonical enum / array-item strings (`"strong"`, `"close-friend"`, `"fearsome"`, …) | Deterministic one-to-one table; a variant not in the table is `needs-input`, not a guess |
| L3 | C# dictionaries keyed by name — `AbilitiesByName`, `SpecialAbilities`, `Upgrades`, `LoadoutByName`, `AvailableGearByName`, `AttributesByName` (with nested `ActionsByName`), trauma `SortedSet` | canonical arrays with a `name` member: `playbook.abilities[]`, `crew.specialAbilities[]`, `crew.upgrades[]`, `gear.loadout[]`, `gear.availableGear[]`, `talent.attributes[]/actions[]`, `monitor.trauma.traumas[]` | Item fields map by name; dictionary key becomes `name`. Ordering is made deterministic (sort by key) and the sort is shown in the preview; the trauma set converts sorted and de-duplicated |
| L4 | C# `DossierVice` has no purveyor | `vice.purveyor` filled `{"name":"","description":""}` | Pure missing-key fill applied to legacy documents; purveyor is a completeness pointer, so the character remains incomplete |
| L5 | C# clocks — `ProjectClock` `{size, time}`; `RolloverClock` `{size, time, rollover}` | `clockKind:"project"`, `segments:time`, `rollover:0` / `clockKind:"rollover"`, `segments:time`, `rollover:<stored>` | Presence of a `rollover` key (even `0`) ⇒ RolloverClock ⇒ `"rollover"`; absence ⇒ `"project"`. A modern-shape document missing `clockKind` is ambiguous → needs input |
| L6 | C3-era crew (contract change 2026-07-29): `contacts`/`factions` absent (optional until formatVersion bump) | `contacts:[]`, `factions:[]` | Q4 makes both required canonical arrays; empty means no entries |
| L7 | Pre-C4 crew (playtest change 2026-08-09): no `turf` | `turf:0` | Bound 0..6 enforced |
| L8 | Legacy C#-era history `snapshotId` (plain GUID, not `^[0-9]{17}-[A-Za-z0-9]+$`) | tolerated on read, never rewritten | History entries are response DTOs; new snapshots use the declared pattern (frontend decoder note, `f2aa`) |

The identity rule (Q15) doubles as a legacy rule: a stored body whose `id`/`kind`
contradicts its directory location is normalized to the route identity.

## 3. Property-path inventory

One row per declared property path of `character.json`, `crew.json`, `clock.json`,
`campaign.json`, and `common.json` (nested objects and array items included;
`[]` marks array items). Column meanings: **canonical default** = the schema-valid
value the canonicalizer fills; **rule** = fill / conversion / needs-input decision;
**class** = `FILL` (canonical default exists), `DERIVED` (settings-derived fill;
`needs-input` when `gameStem` is unresolved), `LEGACY` (explicit legacy rule),
`NEEDS-INPUT` (no derivable value), `IDENTITY` (route/server-generated),
`SPARSE` (claim-overlay exception), `CONST` (fixed discriminator),
`RESPONSE` (server-constructed DTO, no repair semantics).

## 4. Unknown-key rule (no silent loss)

1. `additionalProperties: false` applies to every stored entity object and every
   nested object in the five schemas.
2. An unknown key is **never dropped silently**: the canonicalizer classifies it
   (`undeclared`), and the preview displays its JSON pointer, reason, and previous
   value in the ordered change list.
3. Stored entity: direct access is `422 INVALID_ENTITY`; repair preview is
   `409 NORMALIZATION_REQUIRED` with the removal listed; apply (with token and
   confirmation) writes the document without the key.
4. Inbound import: unknown keys are rejected with `400 INVALID_ENTRY` **unless**
   the caller first runs the import preview, which classifies and displays the
   removal; apply then requires confirmation and the preview token.
5. Known PascalCase legacy keys map via L2/L3 where a rule exists; any other
   unknown key is subject to the same displayed-removal flow.
