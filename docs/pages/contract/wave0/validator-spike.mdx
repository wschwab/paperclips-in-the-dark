# SC-R1 — Ada recursive validator spike

**Verdict: schema-generated entity validators.** No maintained Ada library provides Draft 2020-12 JSON Schema validation (Alire catalog, json-schema.org implementations list, and GitHub all empty; every candidate source read and found to lack schema validation). The decision rule therefore selects generation: the generic-library path fails every exercised requirement, and the generated-validator path passes all of them in the spike. **Dependency impact: zero new dependencies** — the spike compiles against the already-pinned GNAT FSF 16.1.0 + GNATCOLL 26.0.0 core JSON.

This document feeds SC-A1 (recursive validator and canonicalizer) and SC-C5 (schema-derived validator metadata). All commands are re-runnable from `/tmp`; the complete spike source is in [Appendix A](#appendix-a--spike-source-and-reproduction).

## Decision rule applied

Governing decision (`docs/pages/contract/spec-change-work-spec.mdx`, “Validation implementation”):

> Wave 0 first tests whether a maintained Ada library can provide Draft 2020-12 validation, external `$ref` resolution, stable JSON pointers, and usable diagnostics in the current GNAT/Alire toolchain. If it passes the spike, use it. Otherwise generate or centrally define entity-specific recursive validators from the contract schemas. Do not hand-maintain a second unsynchronized set of `Character_Required`/`Allowed` lists.

| Path | Result | Why |
|---|---|---|
| Generic maintained Ada validator | **FAIL** — 0/8 requirements | No such library exists (Section 1). Compile attempts against every candidate fail with `file "...-schema.ads" not found`. |
| Schema-generated entity validators | **PASS** — 8/8 requirements | Spike (Section 2) enforces every required construct from `contract/schemas/*.json` with stable RFC 6901 pointers, on the pinned toolchain, with zero new dependencies. |
| Hand-maintained lists | **REJECTED** | Explicitly forbidden by the governing decision; currently live in `backend-ada/server/src/pitd_callback.adb` lines 800–829 as `Character_Required`/`Crew_Required`/`Clock_Required` — the exact unsynchronized-set anti-pattern this wave removes. |

## 3. Verdict and dependency impact

**Chosen approach: schema-generated entity validators**, per the decision rule — the generic option is unattainable (no maintained Ada JSON Schema validator exists anywhere surveyed), and generation demonstrably covers every construct the contract schemas use, on the pinned toolchain.

**Dependency impact: none.**

- No crate added to `backend-ada/core/alire.toml` or `backend-ada/server/alire.toml`. Validators compile against the already-pinned `gnatcoll 26.0.0` (core-only, no libgpr) and GNAT FSF 16.1.0.
- `gnatprove 16.1.0` is unaffected: validators belong to the SPARK-off AWS server boundary (`server/`), consistent with the A2 architecture note in `backend-ada/AGENTS.md` (“The AWS server is an explicit SPARK_Mode (Off) boundary by design”).
- Licensing: generated code is MIT (repo license), derived from MIT-licensed project schemas — no third-party obligations. The only GPL-licensed candidate (`aor_jsona`) is rejected for lack of a validator API regardless.
- Proof/toolchain interaction: none — the generator runs as a build-time step; generated Ada needs only GNATCOLL.JSON.

**Rejected alternatives:**

| Alternative | Reason |
|---|---|
| `aor_jsona` 1.6.6 | Not a validator (typed extraction only); pulls `aws ^25.2.0` + `gnatcoll ^25.0.0` → `libgpr 25.0.0` stack, which `backend-ada/AGENTS.md` documents as failing on GNAT 16.1; GPL-3.0+exception license. |
| `json` (json-ada) 6.0.0 | Parser only; no schema keywords in source. |
| `yeison` / `yeison_12` | JSON-like structure only. |
| `jwt` 1.0.0 | JWT/JWS signature validation only. |
| `gnatcoll` / `aws` JSON | Parse/DOM only; AdaCore docs: no validation. |
| `matreshka` | XML Schema is not JSON Schema; no JSON Schema module in catalog. |
| C/C++ validator binding (e.g. valijson) | Not a maintained Ada library; no catalog entry; violates the spike question’s terms; would add FFI complexity at the SPARK boundary. |
| Hand-maintained required/allowed lists | Forbidden by the governing decision; currently live in `pitd_callback.adb` (lines 800–829) and already drifting risk (e.g. C3 `contacts`/`factions` requiredness changes). |

## 4. Generator approach sketch (consumed by SC-C5 and SC-A1)

The spike’s validator body **is** the target emission shape. The generator (SC-C5) must be deterministic and idempotent:

1. **Input:** `contract/schemas/{common,character,crew,clock,campaign}.json` — the single source of truth. The generator fails loudly on unsupported constructs instead of emitting a partial validator.
2. **Resolution:** build a per-entity schema tree by inlining external `$ref`s (`common.json#/$defs/…`) and internal `$ref`/`$defs` (`#/$defs/…`), recording the pointer prefix of each inlined def so error pointers stay document-relative. Detect cycles (`$recursiveRef` would be rejected as unsupported; none exist in the schemas).
3. **Emission:** per entity, one package (e.g. `Pitd_Validation.<Entity>`) containing:
   - `Required_<Entity>` / `Allowed_<Entity>` string constants (as in the spike),
   - one `Check_…` procedure per nested object/array item (recursion),
   - one pattern matcher per distinct regex (deduplicated across schemas — the five regexes in the contract schemas),
   - enum membership checks and numeric-bound checks as named procedures,
   - a `Validate (V : JSON_Value) return Error_List` entry point whose `Error_List` carries `(Pointer, Reason)` pairs.
4. **Determinism:** fixed emission order (entities sorted, properties in schema order), fixed traversal order (schema property order), RFC 6901 pointers with 0-based array indices, unknown-key reports ordered by the generator’s emitted allowed-set comparison (not by hash-map iteration). No timestamps or environment-dependent text in output.
5. **Idempotence:** output is a pure function of (schema files, generator version). Generated files are committed; CI regenerates and diffs (`generated == regenerated`) so any schema edit without regeneration fails the gate.
6. **Consumption:** SC-C5 consumes the generator for validator metadata (required/allowed lists, bounds, enum members, patterns) and emits the same lists into the conformance/frontend completeness metadata module; SC-A1 uses the generated `Validate` for inbound checks and the same required/allowed knowledge for canonicalizer fill decisions (spec decision: missing properties normalize to canonical defaults; unknown properties are rejected unless preview-classified). No code path may hand-copy a required list again.
7. **Tooling:** a small dependency-free script (Python stdlib or the repo’s existing Node tooling) run by CI; it emits Ada into `server/src/` only. The spike proves the emitted Ada compiles under `alr build` with `gnatcoll=26.0.0`.

## 5. Answers to the card’s three questions

1. **Contradicted by the codebase?** Two minor toolchain deltas, not contradictions: `gnat --version` reports 16.1.1 (build 20260728) where the card says GNAT FSF 16.1.0 (the alr toolchain is `gnat_native=16.1.0`), and `gprbuild` is not on PATH (26.0.1 runs through `alr build`/`alr exec`). Substantively: `backend-ada/server/src/pitd_callback.adb` (lines 800–829) hand-maintains exactly the `Character_Required`/`Crew_Required`/`Clock_Required` sets the governing decision forbids — confirming the motivation; the schema and the hand lists are in sync today, but the C3 `contacts`/`factions` episode shows the drift risk.
2. **What I had to guess at:** (a) the exact emitted-code shape of the generator (the spike fixes a concrete proposal — `Required_`/`Allowed_` constants plus `Check_` procedures — that SC-C5 may adopt or refine); (b) `format: "date-time"` is treated as an annotation (Draft 2020-12 default) — asserting it would require an explicit contract decision; (c) the spike’s `POINTER <p> REASON <r>` diagnostic format, since the Wave 1 error schema (pointer-level details vocabulary) is not yet frozen; (d) that `snapshotId`/`historyEntry` belongs in scope (it is a campaign `$defs` DTO shape) — harmless either way.
3. **What I needed that wasn’t given:** the final error-message vocabulary and pointer-detail shape for `400 VALIDATION`/`INVALID_ENTRY` responses (the Wave 1 spec task owns it; the spike only proves pointer stability, not the wire format); and a decision on whether the generator should be a Python/Node script or an Ada program (recommended: script run by CI; SC-C5 to confirm). Nothing blocked the spike.

## 6. Toolchain notes (crib notes for `backend-ada/AGENTS.md`)

- `GNATCOLL.JSON.Get (V)` is overload-ambiguous between `UTF8_String`, `UTF8_Unbounded_String` and `XString` in String contexts; use `Ada.Strings.Unbounded.To_String (Get (V))` (the spike’s `S` helper) to disambiguate.
- `GNATCOLL.JSON.JSON_Array` is 1-based; RFC 6901 error pointers require 0-based indices (`I - 1`).
- `gnatcoll=26.0.0` resolves with `gnatcoll_minimal 26.0.0` and **no libgpr** — confirmed again in the spike, matching the existing note.
- `alr --non-interactive init --bin <name>` is the supported non-interactive crate creation (matches the existing cheatsheet).
- The default build profile’s style checks (`-gnatyM` line length, `-gnatww` warnings) emit warnings only; they do not fail `alr build`.
- GNATCOLL object-map iteration order is not contractually stable; deterministic validators must not rely on it for ordering (generator emits ordered allowed-set checks instead).

--  SC-R1 spike driver: validates one JSON document against the
--  generator-shaped recursive validators; prints stable JSON-pointer
--  diagnostics. Scratch code; lives in /tmp only.
--
--  usage: spike <document.json>
--  exit:  0 = valid, 1 = invalid (violations printed), 2 = unreadable

with Ada.Command_Line;
with Ada.Text_IO;
with GNAT.OS_Lib;
with GNATCOLL.JSON;
with Spike_Validators;

procedure Spike is

   use Ada.Text_IO;
   use GNATCOLL.JSON;

   function Read_File (Name : String) return String is
      F    : GNAT.OS_Lib.File_Descriptor :=
        GNAT.OS_Lib.Open_Read (Name, GNAT.OS_Lib.Binary);
      Size : constant Long_Integer := GNAT.OS_Lib.File_Length (F);
   begin
      declare
         Text : String (1 .. Integer (Size));
         Last : Integer;
      begin
         Last := GNAT.OS_Lib.Read (F, Text'Address, Text'Length);
         GNAT.OS_Lib.Close (F);
         if Last /= Text'Length then
            raise Ada.Text_IO.End_Error;
         end if;
         return Text;
      end;
   end Read_File;

   V : JSON_Value;

begin
   if Ada.Command_Line.Argument_Count /= 1 then
      Put_Line ("usage: spike <document.json>");
      Ada.Command_Line.Set_Exit_Status (2);
      return;
   end if;

   begin
      V := Read (Read_File (Ada.Command_Line.Argument (1)));
   exception
      when others =>
         Put_Line ("PARSE_ERROR");
         Ada.Command_Line.Set_Exit_Status (2);
         return;
   end;

   if V.Kind /= JSON_Object_Type then
      Put_Line ("PARSE_ERROR not-an-object");
      Ada.Command_Line.Set_Exit_Status (2);
      return;
   end if;

   if Has_Field (V, "characters") and then Has_Field (V, "crews") then
      Spike_Validators.Validate_Roster (V);
      Put_Line ("ENTITY roster");
   elsif Has_Field (V, "kind") and then Get (V, "kind") = "campaign" then
      Spike_Validators.Validate_Campaign (V);
      Put_Line ("ENTITY campaign");
   elsif Has_Field (V, "kind") and then Get (V, "kind") = "clock" then
      Spike_Validators.Validate_Clock (V);
      Put_Line ("ENTITY clock");
   elsif Has_Field (V, "kind") and then Get (V, "kind") = "character" then
      Spike_Validators.Validate_Character (V);
      Put_Line ("ENTITY character");
   elsif Has_Field (V, "kind") and then Get (V, "kind") = "crew" then
      Spike_Validators.Validate_Crew (V);
      Put_Line ("ENTITY crew");
   elsif Has_Field (V, "snapshotId") then
      Spike_Validators.Validate_History_Entry (V);
      Put_Line ("ENTITY historyEntry");
   else
      Put_Line ("UNKNOWN_KIND");
      Ada.Command_Line.Set_Exit_Status (2);
      return;
   end if;

   for I in 1 .. Spike_Validators.N_Errors loop
      Put_Line ("POINTER " & Spike_Validators.Pointer (I)
                & " REASON " & Spike_Validators.Reason (I));
   end loop;

   if Spike_Validators.Valid then
      Put_Line ("VALID");
      Ada.Command_Line.Set_Exit_Status (0);
   else
      Put_Line (Natural'Image (Spike_Validators.N_Errors) & " error(s)");
      Ada.Command_Line.Set_Exit_Status (1);
   end if;
end Spike;
