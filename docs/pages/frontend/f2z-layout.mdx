# F2z: Sheet Page Layout — Padding, Horizontal Trackers, Card Grid

Fixes the human's 2026-08-08 report: pages rendered flush against the left
edge with no padding or width cap, and trackers (rep, turf, heat, wanted,
stress) stacked vertically instead of running horizontally.

## Themed page container

`/roster`, `/character/{id}`, and `/crew/{id}` (plus their loading/error
states) previously had no container CSS, so they ran full-width and flush
left. They now get the same themed shell the styleguide (`.styleguide`) and
health page (`.health`) already had: centered with `margin: 0 auto`, capped
at `max-width`, padded with `var(--gutter)`.

- Roster uses the standard sheet width `--sheet-width` (920px).
- The detail pages carry more furniture, so they use the new
  `--sheet-width-wide` token (1120px) added to `theme.css`.

## Horizontal trackers

`.stress-track` (the heavy-box idiom shared by the character stress track,
the crew rep/heat/wanted trackers, the crew XP boxes, and the character's
session-expression tracks) used `display: inline-grid; grid-auto-flow: row;`
— boxes stacked vertically. It is now a horizontal flex row that wraps:

```css
.stress-track {
  display: flex;
  flex-wrap: wrap;
  gap: 6px;
  /* …padding/border/background unchanged… */
}
```

`flex-wrap` matters: the rep track can carry 12 boxes (534px laid out), wider
than a half-column card; wrapping keeps it inside the card while still
reading left-to-right. The `.stress-track.rows` variant (three-per-column
stacking) was redefined against the flex base for anyone who opts in.

The other tracker components were already horizontal: `.action-dots`
(`inline-flex`), `.trauma-stamps` (`flex-wrap`), the SVG `.clock`, and the
lair-chart `.chart-boxes` rows. No changes needed there.

## Detail pages use horizontal space

`.character-detail` and `.crew-detail` are now a responsive card grid, same
idiom as `.styleguide .sg-grid`:

```css
.character-detail, .crew-detail {
  display: grid;
  gap: 18px;
  grid-template-columns: repeat(auto-fit, minmax(min(360px, 100%), 1fr));
}
```

Sections pack side-by-side on wide screens (two columns on the wide sheet)
and stack into one column on narrow ones. Every section reads as a box on
the printed sheet (surface-raised card, faint rule, radius), and the
header / footer-strip / notice / closing-action sections span both columns
so the grid never strands a half-empty row:

- **Character**: header (full width); personal+vice, stress+traumas,
  health+talents, playbook+gear, coin+projects pairs; info, notices,
  actions, notes span both columns.
- **Crew**: header (full width); profile+trackers, fund+playbook,
  cohorts+xp pairs; contacts & factions, actions, notices span both columns.
- **Roster**: the two lists sit side-by-side on wide screens (two-column
  grid), stacked on narrow.

## LAYOUT-01 (UX-014) — roster and sheet alignment (2026-08-27)

Wave 7 alignment pass on this page's layout idiom, from the AUDIT-0
remediation card LAYOUT-01. CSS-led, with two small roster TS changes.

### Roster: explicit shared grid starts

The auto-fit grid could park `.roster-characters` beside the masthead and
drop `.roster-crews` nearly 1800px lower, so Crews were only visible after
scrolling past the entire Characters list (DEC-06 finding). The roster now
uses a fixed two-column template with explicit placements: the masthead
spans both columns; Characters claims column 1 row 2, Crews column 2 row 2.
Below 840px everything stacks in one column.

### Roster: Create/import beside the heading

Each section's Create/import disclosure shares one flex scanline with its
heading via a new `.roster-heading-row` wrapper (`justify-content:
space-between`, `align-items: baseline`). DOM order is unchanged, so AT
reading order keeps heading → disclosure → list.

### Sheets: balanced text columns replace paired rows

Sequential pair packing always strands an interior hole beside the shorter
card of each row (measured: 449px dead space under Traumas, 939px beside
Playbook), and no packing discipline can backfill those holes without
reordering DOM or breaking focus order. Wide sheets (≥900px) therefore flow
their section cards through **two balanced text columns**
(`display: block; columns: 2` + `break-inside: avoid`). The sheet reads down
column 1 then down column 2 — visual order equals DOM reading order equals
focus order. Only the masthead and alert strips span both columns; every
span edge would force a rebalance seam below it. Measured worst interior
hole after the change: ≤26px across all widths (was 449px).

### Gear loadout: repeated-row grids

`.gear-loadout-entry` swaps its inline flex for a repeated-row grid
(`minmax(0, 1fr) max-content max-content`): item names wrap inside the fluid
track while bulk text and remove buttons sit on stable max-content tracks,
so every row's ✕ lands on the same x regardless of name length. Verified by
the layout01-alignment journey with two loadout rows.
