# F2u: Crew Sheet — Profile + Trackers

Turns the read-only crew sheet (F2c) into an editable one: the Profile block
(name / lair / hunting grounds / reputation / notes) gets inline editing via
`fields.update`, the Status block becomes clickable trackers (rep — with turf
rendered inside it — heat, wanted), tier and hold get direct controls, and the
Fund block gets coin/stash +/−. Everything follows the F2m/F2y mutation-runner
pattern and reuses the F2y `crewMutate` helper.

## Section → op mapping (per the sheet plan)

| Section | Control | Op | Body |
|---------|---------|----|------|
| Profile | inline edit per field | `fields.update` | `{name?}` / `{lair?}` / `{huntingGrounds?}` / `{reputation?}` / `{notes?}` — only the changed field is sent (contract `minProperties: 1`; server merges) |
| Rep & Turf | box row + −/+ | `rep.add` | `{delta}` |
| Heat | box row + −/+ | `heat.add` | `{delta}` |
| Wanted | box row + −/+ | `wanted.add` | `{delta}` |
| Tier | −/+ | `tier.add` | `{delta}` |
| Hold | native `<select>` + Set | `hold.set` | `{hold}` |
| Coin | −/+ | `coin.add` | `{delta}` |
| Stash | −/+ | `stash.add` | `{delta}` |

## Turf: display-only inside the rep tracker

Sheet-plan decision 5: **turf is not a stored track and has no op**. There is
no turf field in the crew DTO and no turf endpoint — the rep tracker IS the
turf rendering (per the SRD, turf fills rep boxes). The rep tracker therefore
carries a display-only caption noting this; the crew sheet never fabricates
turf state.

## No hardcoded lists or maxima

- **Hold** is a native `<select>` populated from the contract enum: the
  frontend schema's `Hold` literal (`frontend/src/schema/common.ts`) mirrors
  `contract/schemas/common.json#/$defs/hold` (`strong` / `weak`), and the
  page renders one `<option>` per `Hold.literals` — the same values the
  server validates against. If the enum ever grows, the schema and the menu
  grow together.
- **Rep / heat / wanted** box counts come from the DTO's
  `{current, max}` — never hardcoded.
- **Coin / stash** have no maximum in the crew DTO (unlike the character's
  bounded satchel/stash), so the Fund block shows the raw value plus −/+;
  both ops are bounded below at 0 server-side.

## Page structure

- `crew-profile` — one inline-editable field row per free-text field: read
  mode shows the value with a ✎ button; edit mode swaps in a text input with
  ✓ save / ✕ cancel. Save sends only the edited field to `fields.update`.
  The history link lives here too.
- `crew-trackers` — "Rep & Turf" (box row + `current / max` + −/+ with the
  turf caption), "Heat", "Wanted" (same idiom), "Tier" (value + −/+, −
  disabled at 0), "Hold" (`<select>` + Set).
- `crew-fund` — Coin row and Stash row, each a value + −/+ pair (− disabled
  at 0).
- Box clicks follow the F1 styleguide idiom (clickable heavy boxes): clicking
  box N asks to set the value to N; the page computes `delta = N − current`
  and issues the same op the buttons use. The −/+ buttons remain the precise
  accessibility path.

## Client methods added

All eight go through the existing `crewMutate` helper (POST
`/api/crews/{id}/ops/{op}` with `If-Match`, decode `OperationResult`, extract
the updated `Crew`). Stale-revision handling follows F2h: `409` +
`STALE_REVISION` → `StaleRevisionError` → the page re-renders, refetches via
`getCrew`, and shows the "Sheet refreshed because it changed elsewhere"
notice.

| Method | Endpoint | Body | Returns |
|--------|----------|------|---------|
| `crewFieldsUpdate` | `ops/fields.update` | partial fields object | updated `Crew` |
| `crewRepAdd` | `ops/rep.add` | `{ delta }` | updated `Crew` |
| `crewHeatAdd` | `ops/heat.add` | `{ delta }` | updated `Crew` |
| `crewWantedAdd` | `ops/wanted.add` | `{ delta }` | updated `Crew` |
| `crewTierAdd` | `ops/tier.add` | `{ delta }` | updated `Crew` |
| `crewHoldSet` | `ops/hold.set` | `{ hold }` | updated `Crew` |
| `crewCoinAdd` | `ops/coin.add` | `{ delta }` | updated `Crew` |
| `crewStashAdd` | `ops/stash.add` | `{ delta }` | updated `Crew` |

## Error notices

- `StaleRevisionError` from any op → render, refetch, "Sheet refreshed"
  notice (shared `onOpFailure` path, same as F2y).
- Op-level failures surface as `ApiError`s whose body starts with the error
  code: `DUPLICATE` / `NOT_FOUND` get the friendly F2y text, `VALIDATION`
  passes the server message through, anything else falls back to
  `API error (status): body`. The notice renders in a page-level
  `crew-notices` block.

## Remediation updates (Wave 7 — CREW cards)

### Claims: confirm-to-acquire and edit mode (CREW-02)

- **Acquiring a claim is a confirm-first action**: the acquire control asks
  for confirmation before posting, so an accidental click cannot spend the
  crew's claim slot.
- **Removing a claim is intentional, edit-mode removal**: a session-local
  **"Edit claims" / "Done editing"** toggle (`aria-pressed`) gates claim
  removal and customization; while editing, each claim exposes remove and
  customize/reset controls. A warning is shown when removing a claim would
  disconnect it from the connected claim map.
- Regression-pinned by the `crew02-claims` journey (acquire → reload →
  remove) in the six-journey browser suite; the journey also caught a
  backend `claim.set` accumulation bug, fixed in the same card.

### Advancement edit mode (CREW-04)

Ability and upgrade **removal** is gated behind a separate session-local
advancement edit mode (`aria-pressed` toggle); taking and marking stay
one-click. Description layout of abilities/upgrades was fixed in the same
card (UX-010). Pinned by the `crew04-advance` journey.

### Cohorts

Cohort conditional fields and Add-readiness gating are documented on
[F2w — Cohorts](/frontend/f2w-cohorts) (CREW-05).

### Tier / Rep / Turf presentation (DEC-04 routing)

The unified Rep/Turf tracker (Rep fills from the top-left, Turf from the
bottom-right with a next-Turf outline hint) and the settings-derived Roman
numeral Tier display are live in `crew-sections/trackers.ts`. The DEC-04
ruling's bounded crew Stash presentation is **not yet shipped** (the crew
stash still renders unbounded; see `tasks/metrics/frontend/CREW-01.json`
for the honest gap list).
