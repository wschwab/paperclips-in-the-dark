# Unknown operation names answer HTTP 200

**Status: closed by UNKNOWN-OP-01.** The human authorized the contract change;
unknown single-operation names now return **HTTP 400 VALIDATION**, not 200.

The original defect was a `POST /characters/{id}/ops/{name}` with an undeclared
name returning **HTTP 200** with a `VALIDATION` error body. This historical
transport/body disagreement is fixed for single-entity operation admission.

- Observed: `xp.resolve` before its implementation returned 200 with
  `error.code: "VALIDATION"` and `details.issues[0].reason: "unknown operation"`
  (`backend-ada/server/src/pitd_callback.adb`, the generic mutation path).
- Why it matters: a client that checks only the HTTP status treats an unknown
  operation as success. Any tooling that calls a retired or misspelled name is
  misled the same way.

## Decision and fix

Use existing **400 / VALIDATION**: a misspelled or unsupported operation name is
invalid request input, not an absent entity. Existing **404 / NOT_FOUND** remains
for missing resources. The request admission fallback now rejects unrecognized
names before mutation, history or persistence. Declared operations that already
perform their validation during apply retain that behavior. No new code, status,
path or error-envelope variant is introduced.

## Batch reporting is deliberately unchanged

The human clarified that a failed member's VALIDATION/status400 is legitimate
inside a batch report. New `UNKNOWN-OP-BATCH-001` compares an unknown middle
member with a known `stress.add` member whose delta has the wrong type. Both
produce the same **HTTP200 aggregate, ok:true/error:null**, with member outcomes
`[true,false,true]` and a failed member carrying **VALIDATION400**. Both leave
the entire entity, revision and history unchanged.

Aggregate success means the requested outcomes were evaluated, **not** that
every operation succeeded or any write committed. Agents must inspect all
member outcomes. Atomicity concerns writes: one failed member rolls back the
whole batch. Frozen `SEMANTICS-COMPOSITES-002` remains unchanged.

## Red-green evidence

expected400**; the batch comparison already passed. After the fix, all three
pass, and the focused suite plus four unchanged composite cases passes **7/7**.
