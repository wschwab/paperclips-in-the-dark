# French game creation returns HTTP 500

**Status: registered-edition creation fixed by FRENCH-CREATE-01; internal-error
classification gap remains open pending human approval.**
The original exchange below is historical evidence from GAME-MODE-01, not the
current French creation response. The human approved the stem fix and instructed

## Exact observed exchange

Request:

```http
POST /api/characters
Content-Type: application/json
```

```json
{"gameStem":"français-blades-in-the-dark","playbook":"Surineur (Cutter)"}
```

Response: **HTTP 500**, with the existing JSON envelope:

```json
{
  "applied": {"op":"character.create"},
  "error": {
    "code":"VALIDATION",
    "details": {
      "issues": [{
        "expected":"a schema-valid request",
        "pointer":"",
        "reason":"created entity fails schema validation"
      }]
    },
    "message":"created entity fails schema validation",
    "recovery":"Fix the request per the listed issues and retry.",
    "retryable":true,
    "status":400
  },
  "ok":false,
  "sideEffects":[]
}
```

The response is internally inconsistent: the transport is **HTTP 500**, while
`error.status` is **400** and `error.retryable` is **true**. The recovery text
asks the caller to fix a request built from registered game/playbook data.
Neither a new status nor a special-case fallback is proposed here; the bug
needs a separate contract/implementation investigation.

## Evidence and suspected cause

- Game source: `data/games/français-blades-in-the-dark.json`; its first playbook
  is `Surineur (Cutter)` and language is `Français`.
- Exact capture: `tasks/metrics/contract/GAME-MODE-01-french-500.log`.
- Probe used the existing Ada executable through the canonical managed launcher
  with isolated data and a temporary pre-game-mode settings copy (only the new
  `DowntimeSettings` block was removed to permit old-server startup). No backend
  runtime code was changed by GAME-MODE-01.
- **Suspected cause [INFERENCE]:** the unchanged `Character.gameStem` schema
  pattern `^[A-Za-z0-9-]+$` allows ASCII only, but the registered stem contains
  `ç`. This matches the generic “created entity fails schema validation”
  response, but the empty issue pointer does not prove which field failed.
- Human classified the bug as pre-existing. A specific main-revision provenance
  was not independently checked with agent-run VCS, which remained prohibited.

The recommendation at that time was to reconcile the installed catalogue with
accepted stems and investigate transport/envelope classification together.
FRENCH-CREATE-01 below proves the stem cause; the internal branch still awaits
human approval rather than being relabeled as bad input.

## FRENCH-CREATE-01: proved cause and authorized contract change

The new isolated DTO probe changes **only gameStem** on an otherwise valid
created scoundrel. Before the fix, AJV reports exactly
`/gameStem must match pattern "^[A-Za-z0-9-]+$"` for the catalogue’s French
stem. The live edition test separately returns HTTP 500, and the envelope test
separately fails on HTTP 500 versus error.status 400. These are observed RED
failures, not a guess from the spelling of the filename.

The code chain is:

- `backend-ada/server/src/pitd_ops.adb:99` copies the requested stem unchanged
  into the new DTO.
- `backend-ada/server/src/pitd_stored.adb:54` runs the generated character
  validator at the persistence gate.
- `backend-ada/server/src/generated/pitd_schema_validators.adb:1405` validates
  gameStem with Check_Game_Stem; its checker starts at line 219.
- `contract/schemas/character.json:44` was the source ASCII-only pattern;
  `skill/generate-ada-validators.mjs:158` selects its generated checker.

The human authorized changing game-stem constraints to
`^[A-Za-z0-9À-ɏ-]+$`: existing ASCII alphanumerics/hyphen plus Latin-block
code points U+00C0–U+024F. This accepts every currently registered edition,
not a special case for French or a hardcoded list of stems. The Ada checker
recognizes exactly those UTF-8 encodings without allocating a decoded copy.
Character, crew and campaign schemas, corresponding OpenAPI game-stem fields,
and the conformance Effect mirror move together. UUID/entity/snapshot ID
constraints are unchanged. Canonical artifacts are regenerated.

The new suite enumerates **data/games/games.json**, not every JSON file in the
directory (which also contains schemas, crew settings and demo documents).
It takes each edition’s first playbook from that edition’s data. Observed
focused GREEN: **6/6**, covering all four registered editions, typed and strict
contract decoding, isolated stem admission, and existing request/domain-error
envelope controls. French creation now succeeds without changing New_Character
defaults, which further isolates the root cause.

## Open: server-generated invalid entity has no internal contract branch

A valid request whose server-generated DTO fails its own schema is a **server
defect**, not client VALIDATION. No INTERNAL/SERVER_ERROR/500 error variant
exists in the current contract or typed error constructors:

- `backend-ada/server/src/pitd_callback.adb:352` (Persist_Create) requests
  HTTP 500 with the backend label INTERNAL.
- `backend-ada/server/src/pitd_common.adb:910–911` (Error_Result) maps every
  unrecognized label to Validation_Error.
- `backend-ada/server/src/pitd_error.adb:99` constructs VALIDATION with status
  400 and retryable true, causing the observed transport/body disagreement.

The human explicitly instructed FRENCH-CREATE-01 to **leave this path’s
classification unchanged** while requesting approval for an internal branch.
No new code/status, client-error relabeling, or suppression is introduced here.
The remaining open decision is the approved internal-error contract variant
and its non-client recovery semantics. The catalogue fix prevents the French
request from reaching this defective path; it does not claim the generic
invariant-failure envelope has been fixed.
