Pre-existing footgun, not introduced here, but: (a) cleanup of the polluting entities is recorded nowhere, and (b) the default remains a silent trap. Concrete fix: require `CONFORMANCE_BASE_URL` explicitly (no default) or route `test:run`/`test:tooling` through the guards; then record the cleanup.

**P2 — Probe under-asserts what the card claims.** `tasks/NOTES-EDIT-01.md` states "touch targets >= 44x44 for Edit, Save, Cancel"; the probe asserts character Edit/Save/Cancel and crew **Save only** (`notes-edit-01-chromium-probe.mjs:71-74,81`) — crew Edit and crew Cancel are unasserted. Behavior is in fact correct: my independent probe measured all six ≥44×44 (`.note-edit-control` covers both sheets). Fix is one line per locator in the probe.

**P2 — "Cancel note N(+1) edit" is sheet-specific.** True for characters (`character-sections/notes.ts:109`, 1-based `idx+1`); the crew uses the 0-based index (`crew-sections/notes.ts:110`, `Cancel note 0 edit`), consistent with the crew's existing `Remove note ${idx}`. Not a defect, but the claim as written generalizes incorrectly.

**P2 — Untested failure path.** No test pins "noteEdit survives a failed/stale save" (character `:1411-1420`, crew `:879-885`). Code is correct; the edge is unpinned.
