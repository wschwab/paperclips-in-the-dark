## P2 — Stale-revision refresh silently discards a custom expert type edit

**Source:** `frontend/src/pages/crew-sections/cohorts.ts:159–164` (`editDraftFor`); resulting save behavior at lines `248–251` and `298–299`.

**Reproduction**
1. Create an expert with type `Old specialty`.
2. Open Edit. Change its custom type to `Local specialty` and description to `Local custom description`.
3. From another client, change that expert’s type to `Doctor`.
4. Save the original editor. The server returns `409 STALE_REVISION`; the sheet refreshes.
5. Retry Save.

**Observed:** Refresh changes the type selector from **Custom** to **Doctor**, hiding the locally edited custom text. Retry sends only:
```json
{"cohortId":"…","description":"Local custom description"}
```
The request succeeds and closes the editor. Both the displayed cohort and fetched crew retain `expertType: "Doctor"`; the user’s custom-type edit is lost.

**Cause:** `editDraftFor` rebases `expertType` and `expertCustom` independently, although together they represent one persisted field. The unchanged `Custom` selector is overwritten despite its associated text being dirty. These controls need to be rebased as one logical field.

**Evidence:** `/tmp/sol-review/crew-review-r7-cohort-evidence/results.json`, checkpoints `custom-type-local-draft`, `custom-type-after-stale-refresh`, and `custom-type-after-retry`. Screenshots and per-combination JSON are in the same directory.
